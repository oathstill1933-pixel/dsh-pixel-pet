# 兼容矩阵（COMPAT_MATRIX）

DSH / 主插件 / 包协议 / 环境组件四个层级的兼容记录，四类**不混成一个版号**（方案 §九）。本文件是记录性文档，没有代码权威实现；每次升级按 §3 流程续写，**没验证过就写"待验证"，不许拿声明范围当验收**。

## 1. 矩阵格式

四张表，各列：

1. **DSH ↔ 主插件/DSH 适配器**：DSH 精确版本 | 主插件版本 | 平台 | 验证方式 | 结论（已验证 / 待验证 / 已知不兼容）| 日期
2. **主插件 ↔ 包协议**：主插件版本 | packApi | manifestVersion | 结论
3. **包 ↔ 引擎/provider/角色动作**：包 packApi | 引擎 id@版本 | 依赖能力 | 结论
4. **Node/Python/图形音频组件 ↔ 平台**：组件 | 版本 | 平台 | 结论

「验证方式」必须写实际做过的事（隔离 Profile 冷启动激活 / 一条消息→工具→回复 / 禁用释放），**HTTP 200、类型检查或源码目录存在不算验证**。

## 3. 每次 DSH 升级的维护流程

先记录旧基线与精确新版本 → 对照完整版本走廊与七类触点清单（升级技能 `dsh-plugin-upgrade-skill`）→ 隔离 Profile（独立 DSH_HOME / 桌宠 dataDir，关自动安装与真实 TTS 预热）跑旧基线测试 → 按证据适配 → 构建并检查实际发行产物 → 新宿主冷启动验证激活 → 完整核心业务流 → 出具支持矩阵与回退说明后发布。

- 区分「磁盘已升级、进程尚未重启」的旧运行实例；插件版本、DSH 版本、Cordis 版本分开记录。
- RC/alpha 范围按目标宿主实际 SemVer 实现验证，`^x.y.z` 不默认包含同版本预发行（packkit 的范围实现按标准 SemVer 处理，见 PACK_SPEC §2）。
- 未验证的新宿主：显示「待验证」，先探测已知契约；方法同名不当作兼容。已知不兼容：禁止相应玩法启动，显示受影响范围，不清空包、不覆盖设置。

## 4. 明确不承诺的事

- 不保证 DSH 每个未来版本零改动兼容；不用特别宽的版本范围代替测试。
- 主插件被 DSH 在安装/激活阶段拒绝时，内部自检与降级提示可能根本执行不到——这类故障靠发布元数据与外部恢复说明处理，不声称运行时 try/catch 能兜住。
- 回滚主插件只涵盖它拥有的包、配置、快照；DSH 自身的会话日志/存储不做降级承诺。
