# 跟随外部桥会话（Follow Pointer v1）

桌宠平时连的是设置页里手填的那一个会话。如果你的聊天桥（把某个平台的消息转进 DeepSeek Harness 的程序）
**每天新开一间房**，手填的指针就会过期，桌宠对着空气说话。

「跟随」让这件事自动化：**桥写门牌，桌宠认门牌**。桥每次新建或切换会话，写一个 JSON 文件；桌宠每
20 秒看一眼，门牌指向哪个会话就跟到哪个会话。桌宠不认桥、不认平台，只认这个文件。

一句话：**桥负责把门牌写好，桌宠负责认门牌；谁写的桥、接的哪个平台、多久换一次房，桌宠都不关心。**

## 前提（先看这一段）

- **桥和桌宠必须在同一台电脑上，用的是同一个 DeepSeek Harness。** 门牌文件在本机目录里，
  门牌里的会话 id 也只在这个 DSH 里有效；HTTP 方式也只收回环地址（`127.0.0.1` / `localhost`）。
- 跨机器照着做是找不到的。以后也不打算支持远程门牌：那等于给外部开一个把桌宠改道到别处的口子。

## 门牌长什么样

一个来源一个文件，放在：

```
%LOCALAPPDATA%\dsh-pixel-pet\follow\<channel>-<peer>.json
```

（设置里改过「门牌目录」的话就是那个目录；面板上「跟随」那一栏会显示实际路径。）

```json
{
  "schema": "dsh-pixel-pet/follow@1",
  "channel": "myapp",
  "peer": "10000",
  "scope": "direct",
  "petHome": true,
  "sessionId": "session-00000000-0000-4000-8000-000000000000",
  "label": "私聊",
  "updatedAt": "2026-11-15T22:30:00+08:00",
  "ttlHours": 36
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `schema` | ✅ | 固定 `dsh-pixel-pet/follow@1`（= 插件包名）。版本不匹配的文件会被安静忽略，不报错 |
| `channel` | ✅ | 通道名，`^[a-z0-9_-]{1,32}$`。`qq` / `discord` / `telegram` / 自建的名字都行，**桌宠不解析它的含义** |
| `peer` | ✅ | 对端标识，`^\S{1,64}$`（号码、频道 id、房间名都行） |
| `scope` | ❌ | 自由串（建议 `direct` / `group` / `channel` / `thread`）。用于面板分组显示；是多人场合的词时桌宠一律不跟（见下文「只拦不放的闸」） |
| `petHome` | ✅ | 桥自己声明「这个来源适不适合当桌宠的家」。缺失按 `false` 处理 |
| `sessionId` | ✅ | 当前该来源所在的 DSH 会话 id，带不带 `session-` 前缀都行 |
| `label` | ❌ | 人类可读名字，只用于面板显示 |
| `updatedAt` | ✅ | ISO 8601 带时区；桌宠用它判断新旧和过期 |
| `ttlHours` | ❌ | 过期时长，1～720，默认 36 |

同一个来源出现在多个文件里时，取 `updatedAt` 最新的那个。单个文件超过 4 KB、`.tmp` 文件、
符号链接、以 `.` 开头的文件都会被跳过；坏文件只丢它自己，面板上会有一行黄字说明。

### 为什么有 `petHome`

被跟随的会话就是桌宠的「家」，这些内容都会进到它里面：桌宠提示词里的「近日」行（生日、待办标题）、
余额行、活动感知、看书划词、截图。群聊里有人 @ 它的时候，AI 完全可能把这些说到群里去。

所以**只有 `petHome: true` 的来源会被跟随**。哪个来源算「适合当家」由桥自己判断——
一对一私聊填 `true`，群、频道、多人房间填 `false`。桌宠**不看** `channel` 是什么：它不认识任何平台，也不需要认识。

另有一道**只拦不放**的闸：`scope` 是下面这些表示多人场合的词时（不分大小写），`petHome` 填 `true` 也不会被跟随——
防的是桥把群误标成 `true`：

`group` `groups` `supergroup` `channel` `guild` `server` `room` `chatroom` `forum` `community` `team` `public`
`群` `群聊` `群组` `频道` `房间` `社区` `公开`

`scope` 不填，就完全按 `petHome` 来。「只有你和 AI 两个人的小群」这种名义上是群、实际上是私聊的来源，
桥不填 `scope`（或填 `direct`）、`petHome` 填 `true` 即可。

## 桥这边要做的三件事

### 1. 写门牌

每次给某个来源新建或切换会话之后，原子地写一个 JSON（先写 `.tmp` 再 rename）：

- 一个来源一个文件：`<channel>-<peer>.json`，文件名随便（桌宠只读内容），但另外写就别重名；
- 只写上面那些字段，别写 token、密码、cookie、聊天内容；
- 写失败不能影响聊天本身：`try/catch` 掉，记一行日志就行；
- **从不切房的桥也照写一次**：内容不再变，桌宠就一直跟着，没有副作用。

`examples/follow/` 里有可直接抄的最小实现（Node 写文件、Python 写文件），还有「不外发」那一半的伪代码。
桥本身已经有本机 HTTP 端口的话，也可以让 `GET /follow` 直接返回同样的 JSON（单个对象或数组），
设置里的「HTTP 门牌」只收回环地址、3 秒超时、响应不超过 4 KB。

### 2. 桌宠的轮次不外发

桌宠发进会话的每条消息都带 `source.kind === "pixel-pet"`，id 也统一以 `pixel-pet-` 开头
（`user/message` 事件的 `data.source` / `data.id`，读得到就是前者）。

桥在决定「这一轮的 AI 回复要不要发回平台」时：

- 触发这一轮的那条用户消息 `source.kind === "pixel-pet"` → **一律不外发**，哪怕它落在你的「唤醒尾巴」时间窗里；
- 记一行日志「本地轮，不外发」；
- 拿不到 `source` 字段的老环境，按 id 前缀 `pixel-pet-` 判断，效果一样。

### 3. 给转进来的消息打来源（可选，推荐）

桥转发平台消息进 DSH 时，在 followup 的 `source` 里写
`{ kind: "<你的桥名>", channel: "<通道名>", peer: "<来源标识>" }`。
不要把号码写进对话文本——桌宠和面板都不需要它出现在对话里。

三件事都是**纯增量**：不写门牌 = 桌宠保持手动模式，原有功能完全不受影响。

## 自检

宿主有个只读接口 `GET http://127.0.0.1:<端口>/dsh-pixel-pet/api/follow`（只认本机同源）：

```json
{
  "ok": true, "mode": "follow", "source": "myapp/100****000", "label": "私聊",
  "effectiveSessionId": "…a1f3c2d9", "manualSessionId": "…9f0d1b22",
  "lastKnown": { "sessionId": "…a1f3c2d9", "label": "私聊", "at": 1763255400000 },
  "sources": [{ "source": "myapp/100****000", "channel": "myapp", "peer": "100****000",
                "label": "私聊", "scope": "direct", "petHome": true,
                "updatedAt": "2026-11-15T14:30:00.000Z", "stale": false,
                "sessionOk": true, "eligible": true }],
  "warning": ""
}
```

- `peer` 与会话 id 都是脱敏的（`100****000` / `…a1f3c2d9`），可以直接贴给别人看。
- `eligible: false` = 这个来源当不了桌宠的家（`petHome` 不是 `true`，或者那个会话已经不在了 / 已归档）。
- `warning` 非空就是当前正在降级：门牌没了、过期了、格式坏了、指向的会话不存在……

验收清单：

1. `sources` 里能看到你的来源，`sessionOk` 和 `petHome` 都是 `true`；
2. 在桌宠面板选中这个来源、切到「跟随」，再在平台上触发一次切换会话：20 秒内
   `effectiveSessionId` 变成新会话，桌宠冒一句「搬到新会话了」；
3. 对桌宠说一句话：这一轮的回复**不应**出现在平台上，你的日志里有「本地轮，不外发」；
4. 删掉门牌：面板出现黄字，桌宠仍能用上次的会话（不会失联、不会崩）。

## 坏了会怎样

| 情况 | 桌宠的行为 |
|---|---|
| 门牌文件被删 / 写坏（非法 JSON） | 保持「上次已知会话」，面板一行黄字，绝不静默指向空 |
| `updatedAt` 超过 `ttlHours` | 同上 |
| 连续 3 次读不到门牌 | 同上（文案变成「连续读不到门牌」） |
| `petHome` 不是 `true` | 不跟随，面板里这一项置灰：这个来源不适合当桌宠的家 |
| `scope` 是多人场合的词（`group` / `channel` / `群聊` …） | 不跟随，`petHome` 填什么都一样；`/api/follow` 里这一项 `multiParty: true` |
| 指向的会话不存在或已归档 | 不切，保持上次已知会话并给 warning |
| 一次都没跟到过 | 退回设置里手填的那个会话，并给 warning |

切换会话**不打断正在进行的那一轮**：切换只改「下一句发去哪儿」，已经发出去的消息照常回来、照常念。
「上次已知会话」存在 `<数据目录>\follow-state.json`，重启后能接着跟。

## 关掉

设置页「跟随」切回「手动」，行为立刻回到升级前：用你在设置里手填的那个会话。
手填值在跟随模式下**永远不会被覆盖**——跟随只是读取时换个会话，不写你的设置。
