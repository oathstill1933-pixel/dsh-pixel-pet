# 权限表（PERMISSIONS）

拓展包能向用户申请的全部权限。表本身冻结在 [contracts/pack-contract-v1.json](../contracts/pack-contract-v1.json) 的 `permissions`；本文件是它的解释。未知权限 id → `E_PERMISSION_UNKNOWN`，包不得激活。

权威实现：`lib/packkit.js` / `runtime/pixelpet/packkit.py` 的 `describePermission`；执行门在各受审计引擎与宿主路由（本表不新增执行点）。

## 1. 权限一览（v1）

| 权限 id | 含义 | 运行是否联网 | 需要确认 |
|---|---|---|---|
| `docs.read` | 读取用户明确选定的本地文档与选中文段 | 否 | ✓ |
| `model.ask` | 把用户确认范围的内容发给模型会话并取回复 | **是** | ✓ |
| `playback.status` | 读取本地播放状态（曲目/播放暂停） | 否 | — |
| `playback.control` | 控制本地播放（播放/暂停/切曲/队列） | 否 | ✓ |
| `voice.capture` | 麦克风收音 | 否 | ✓ |
| `screen.capture` | 屏幕截图 | 否 | ✓ |
| `proactive.schedule` | 定时或主动发起动作 | 否 | ✓ |

要点（对应方案 §十）：

- **文档权限限定用户选定对象**，不默认授予全盘读权限。
- **联网与模型请求显示发送内容边界**；配置从用户自己的设置获取，不继承包作者的密钥。启用联网前提示发送范围，默认只发本次选中文段/明确确认的上下文。
- **音乐读状态和控制分开**（status 不需要确认，control 需要）；麦克风与截图不因装了家具自动放行。
- **定时或主动动作是单独开关**，不以下载包等于同意后台运行。
- 功能卡必须分别标明「安装是否联网」「运行是否联网」「是否需要额外组件」；v1 声明式包安装一律不联网。

## 2. 授权规则（冻结）

1. 无敏感权限且用户点的是「安装并启用」，可以一次完成；涉及上表任一「需要确认」的权限，**必须先确认，再实际启动玩法**。
2. 已装包更新新增权限时**暂停新增能力**，等待用户授权；拒绝授权只停用对应能力，不卸包。
3. 拒绝后不启动该能力，也不降级偷跑：显示「会话未授权 / 权限未授予」，不自动解除限制。
4. 权限执行失败对用户可见（缺能力 ≠ 静默无操作）；包的本地日志只记录诊断必要信息，不落文档正文、歌词全文、账号/密钥或语音样本。

## 3. 与能力（capabilities）的区分

能力（`requires.capabilities`，见 ENGINE_SPEC.md）是核心暴露给引擎的接口面；权限是用户授予的敏感操作。一个包通常两者都声明：能力决定"能不能调到"，权限决定"允许不允许调"。只声明能力不声明对应权限的包，运行时按未授权处理。
